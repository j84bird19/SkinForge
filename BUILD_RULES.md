## LOCKED WORKFLOW

1. Preserve project context between revisions.
2. Before a major revision, summarize:
   - Current State
   - Locked Systems
   - What Will Change
   - What Will Not Change
3. Once a system is confirmed working, **LOCK IT**.
4. Never modify a locked system unless the user explicitly requests it.
5. Modify only the requested subsystem.
6. Diagnose root causes instead of applying random patches.
7. Keep stable systems intact.
8. Work on one subsystem at a time.
9. Do not redesign the interface without approval.
10. The user’s approved visual is the master blueprint.
